# لبيه | منصة الطلبات والتوصيل المحلي

منصة متعددة المتاجر لمدينة عزان بمحافظة شبوة، بواجهة عربية RTL وعملة الريال اليمني. مبنية على Next.js 14 (Pages Router) وSupabase (Auth / Postgres / Storage / Realtime) وOpenStreetMap، وجاهزة للنشر على Vercel بعد إكمال إعدادات البيئة وقاعدة البيانات الموضحة أدناه.

> حالة التحقق: تم التحقق من نجاح `npm run build` واختبار الصفحات العامة في المتصفح. مسارات تسجيل الدخول بالبريد وقواعد البيانات والصلاحيات **لم تُختبر بعد على مشروع Supabase حي**، وتسليم البريد الإلكتروني للإنتاج **متوقف على إعداد نطاق المُرسل** (راجع [ENVIRONMENT-SETUP.md](./ENVIRONMENT-SETUP.md)). لا يُعد المشروع مكتملًا إنتاجيًا قبل إنهاء [TEST-CHECKLIST.md](./TEST-CHECKLIST.md).

## الميزات

### العميل
- رئيسية حقيقية: متاجر نشطة فقط، بحث، تصنيفات ديناميكية، الأقرب عبر الموقع الجغرافي، حالات تحميل/فراغ/خطأ.
- صفحة متجر: غلاف وشعار وحالة فتح/إغلاق، تصنيفات وزر شراء سريع، تفاصيل المنتج والمخزون.
- سلة محفوظة محليًا مع منع خلط متجرين، تعديل الكميات، وتحقق لحظي من المخزون.
- إتمام الطلب: بيانات العميل والعنوان والموقع والملاحظات، ورسم توصيل يُحسب على الخادم.
- طلب خاص (عنوان + وصف + صورة اختيارية) وطلب شي إن (رابط أو صورة + مقاس/لون/كمية).
- صفحة حساب: تعديل الاسم والجوال، الطلبات الثلاثة، ردود الإدارة، وتسجيل الخروج.
- تتبع الطلب: خط زمني، عناصر وفواتير، خريطة OpenStreetMap وموقع السائق عند توفره، تحديث Realtime مع استعلام دوري احتياطي.

### التاجر (مدير المتجر)
- لوحة مؤشرات ومبيعات حقيقية، قائمة الطلبات الواردة وقبولها (تجهيز) أو رفضها (إلغاء).
- إدارة المنتجات: إضافة/تعديل/إخفاء/حذف ورفع الصور.
- إدارة بيانات المتجر: الاسم والوصف والتصنيف والهاتف والإحداثيات والشعار والغلاف وحالة الفتح.
- عزل كامل: التاجر لا يرى إلا متاجره وطلباتها.

### السائق
- مشاركة الموقع كل 10 ثوانٍ بعد منح الإذن.
- الطلبات المسندة فقط، مع بيانات التسليم اللازمة، وبدء التوصيل وتأكيد التسليم.
- سجل الطلبات المنتهية وروابط خرائط للمتجر والعميل.

### مدير المنصة
- إحصاءات حقيقية من قاعدة البيانات (عملاء/متاجر/طلبات/سائقين).
- إدارة الطلبات الثلاثة، إسناد السائقين، تسعير طلبات شي إن، وردود الطلبات الخاصة.
- إدارة المتاجر (إنشاء/تفعيل/إيقاف/فتح/إغلاق) وربط مالك المتجر.
- إدارة المستخدمين والأدوار عبر RPC إداري محمي، مع منع تعديل دور الحساب الذاتي.
- إعدادات المنصة: العمولة، رسم الأساس، رسم الكيلومتر، وبيانات التواصل.

## التقنيات

- Next.js `14.2.31`، React `18.3`، JavaScript بدون TypeScript.
- `@supabase/supabase-js` v2: Auth (Email OTP)، Postgres + RLS، Storage، Realtime.
- Tailwind CSS وملف تصميم مخصص `styles/extra.css`، خط Cairo، RTL.
- OpenStreetMap عبر iframe وروابط إحداثيات.
- Vercel للنشر.

## إعداد قاعدة البيانات (بالترتيب الإلزامي)

نفّذ الملفات التالية مرة واحدة في Supabase SQL Editor بهذا الترتيب:

1. `supabase/schema.sql` — الجداول والفهارس والدوال وRLS والتخزين وRealtime.
2. `supabase/email-auth-migration.sql` — حفظ الاسم والجوال الاختياريين عند التسجيل بالبريد.
3. `supabase/production-hardening.sql` — ترحيل إضافي غير هدّام: ملاحظات الطلبات، عنوان/صورة/رد الطلب الخاص، بيانات المتجر الإضافية، سياسات وحمايات الأدوار، حذف المنتجات، حاوية `product-images`، ودالة إدارة المستخدمين.

التفاصيل والتحقق: [DATABASE-MIGRATIONS.md](./DATABASE-MIGRATIONS.md).

## متغيرات البيئة

انسخ `.env.example` إلى `.env.local` ثم املأ:

| المتغير | إلزامي | الوصف |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | نعم | رابط مشروع Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | نعم | مفتاح anon/publishable العام |
| `NEXT_PUBLIC_CONTACT_PHONE` | لا | رقم التواصل في التذييل (تُقدّمه إعدادات قاعدة البيانات عليه) |
| `NEXT_PUBLIC_WHATSAPP_NUMBER` | لا | واتساب بصيغة دولية بدون `+` أو مسافات |
| `NEXT_PUBLIC_SOCIAL_INSTAGRAM` | لا | رابط إنستغرام |
| `NEXT_PUBLIC_SOCIAL_FACEBOOK` | لا | رابط فيسبوك |

لا تضع `service_role` في أي ملف يبدأ بـ `NEXT_PUBLIC_` ولا في المتصفح. راجع [ENVIRONMENT-SETUP.md](./ENVIRONMENT-SETUP.md) لإعداد البريد والتخزين وRedirect URLs.

## التشغيل محليًا

```bash
npm install
cp .env.example .env.local
# املأ قيم Supabase في .env.local
npm run dev
```

افتح `http://localhost:3000`. لبناء الإنتاج:

```bash
npm run build
npm start
```

## تسجيل الدخول والأدوار

- الدخول برمز OTP عبر البريد الإلكتروني فقط. لا يوجد دخول برقم الجوال ولا كلمة مرور ثابتة.
- الحساب الجديد يُنشأ بدور `customer` فقط، ولا يمكن اختيار دور إداري من الواجهة.
- بعد التحقق يُوجَّه المستخدم حسب الدور: `admin → /admin`، `merchant → /store-admin`، `driver → /driver`، `customer → /` أو الصفحة المطلوبة الآمنة.
- لإنشاء أول مدير وحسابات التشغيل: [supabase/ADMIN-SETUP.md](./supabase/ADMIN-SETUP.md).

## رسوم التوصيل

- 1000 ر.ي لأول 2 كم.
- 300 ر.ي لكل كيلومتر إضافي، مع تقريب المسافة الإضافية **لأعلى**: 2.1 كم = كيلومتر إضافي واحد، 3.1 كم = كيلومتران إضافيان.
- تُحسب على الخادم داخل `place_market_order` ولا يعتمد على قيمة يرسلها المتصفح. القيم قابلة للتغيير من إعدادات المدير.
- المسافة خط مستقيم (Haversine) بين إحداثيات المتجر والعميل، وليست مسافة قيادة فعلية.

## الصلاحيات والأمان

- RLS مفعّل على جميع الجداول، مع سياسات قراءة/تحديث مقيّدة بالدور والملكية.
- حماية من تصعيد الصلاحيات: لا يمكن للمستخدم تغيير دوره أو ملكية متجره؛ التاجر يحدّث حالة الطلب إلى `processing` أو `cancelled` فقط، والسائق إلى `on_delivery` أو `delivered` فقط.
- بريد المستخدمين متاح للمدير فقط عبر `admin_list_users()`، دون توسيع قراءة جدول `profiles` للعملاء أو السائقين.
- رفع الصور محمي بسياسات تخزين تربط مجلد المتجر بمالكه.
- لا توجد مفاتيح خدمة داخل كود المتصفح، ولا بيانات تجريبية أو إحصاءات وهمية.

## النشر على Vercel

1. ارفع المستودع إلى GitHub واستورده في Vercel.
2. أضف متغيرات البيئة نفسها في Project Settings.
3. أضف دومين الإنتاج إلى Supabase Authentication > URL Configuration (Site URL وRedirect URLs)، مع `http://localhost:3000/**` للتطوير.
4. راجع [DEPLOYMENT-CHECKLIST.md](./DEPLOYMENT-CHECKLIST.md) قبل التسليم.

## القيود المعروفة

- البريد: إعداد Resend التجريبي يرسل فقط إلى بريد مصرح به. تسليم البريد لجميع المستخدمين يتطلب التحقق من نطاق مُرسل مملوك للعميل — **BLOCKED BY EXTERNAL CONFIGURATION**.
- لا توجد بوابة دفع إلكتروني؛ الدفع عند الاستلام حاليًا.
- لا يوجد ربط آلي مع شي إن؛ الطلبات تُراجع يدويًا من المدير.
- لا توجد اختبارات آلية (E2E/Unit) بعد؛ الاختبارات موثقة يدويًا في [TEST-CHECKLIST.md](./TEST-CHECKLIST.md).
- مسار التوصيل حسابي مباشر وليس مسار قيادة على الطرق.
